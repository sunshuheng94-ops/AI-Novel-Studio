# AI 小说工作台

AI 小说工作台是一个面向中文长篇网文创作的本地桌面软件。它把作品设定、长篇蓝图、分卷、章节卡、正文生成、自然读感检查和本地项目管理放在同一个工作流里，适合需要持续自动连载、反复试写和维护长篇一致性的作者使用。

当前版本：`1.8.6`

## 核心能力

- 本地多用户账号：支持注册、登录、退出登录，不同账号的作品库互相隔离。
- 本地作品库：作品、章节、章节卡、角色、时间线、分卷、自动写作台账都保存在本机。
- 多模型配置：支持 DeepSeek 与 GPT-5.5 配置，支持按阶段使用不同模型。
- 长篇蓝图生成：根据题材、读者定位、文风和核心设定生成长期连载规划，并用完整性标记防止截断蓝图覆盖旧规划。
- 自动分卷：按长篇蓝图拆分卷定位、卷目标和卷末钩子。
- 章节卡生成：章节卡只管理剧情轨道，包括目标、事件、人物、线索、结果、伏笔和章末钩子。
- 正文生成：支持当前章生成、继续自动写作、写到指定进度，自动推进采用逐章流式保存。
- 流式预览：章节卡、当前章正文和自动续写章节可以边生成边显示，最终解析清理后再保存。
- 轻量生成模式：跳过重控制链路，保留蓝图、作者人设、章节卡和最近上下文，更适合快速试写。
- 长篇自动台账：自动维护伏笔、读者期待、爽点、角色记忆、角色长期摘要、系统规则和章节功能日历。
- 台账重建：可根据已写正文和章节卡重建自动写作台账，把旧章节重新计入长篇记忆。
- 自然读感守门：检测并修复 Markdown 痕迹、机械否定句、三项名词排比、碎句链、短台词链、清单式否定台词和模板钩子。
- 检查点机制：长篇写作过程中可做20章阶段检查和100章大阶段检查，复盘伏笔、角色状态、系统规则、卷结构和后续方向。
- 二次元工作台：自动写作中心使用任务卡片组织流程，非概览页提供 Live2D 助手坞显示当前状态。
- 导出能力：支持导出项目 JSON、章节 TXT 和本地桌面安装包。

## 推荐工作流

1. 新建作品，填写作品名、类型、目标读者、核心设定和文风要求。
2. 在 AI 配置中保存模型 Key、模型名和 Base URL。
3. 生成长篇蓝图，确认主线、卷结构、角色成长线和核心卖点没有跑偏；如需人工修订，可以直接保存蓝图修改。
4. 自动分卷，检查每卷定位、目标和卷末钩子。
5. 每次生成 3 章章节卡，确认剧情轨道是否符合预期。
6. 使用当前章生成、继续自动写作或写到指定进度生成正文。
7. 观察流式预览；每章生成结束后由解析、清理和自然度检查链路保存最终稿，再进入下一章。
8. 每 20 章左右做一次阶段检查，修正连续性记忆、伏笔台账和后续章节卡；每 100 章做一次大阶段检查，判断是否需要重排章节卡、重新分卷或保存建议到蓝图。
9. 如果旧项目已经写过多章，使用“重建自动写作台账”把既有正文重新纳入角色记忆、伏笔、期待和系统规则。

- 轻量模式检查改为关注能力或设定边界，更适配宝可梦、修仙、同人和无系统题材。
- 报告结构编号顺延，下一阶段写作指令仍保留可直接喂给自动写作的格式。
- GitHub 源码切换为无 Live2D 版本，安装包仍可单独保留正常版与无 Live2D 版产物。

## 1.8.4 更新重点

- 新增作品风格驾驶舱，可设置主基调和日常、冒险、爽点、反差、高压混合比例。

- 新增每 5 章基调诊断开关，关闭后不再自动诊断，也不会把旧诊断建议注入后续章节卡和正文。
- 章节卡和正文生成会读取作品基调协议，让轻松日常、轻喜反差、冒险成长、爽文升级、高压求生和群像史诗有不同推进方式。
- 发布安装包时同时提供正常版和无 Live2D 版；仓库不跟踪本地 Live2D 模型资源，避免把未确认授权的形象文件提交到 GitHub。

## 1.8.3 更新重点

- 新增句子流动性守门，避免把“段落短、解释少”误写成缺词、短句链或分镜标签。
- 轻量生成新增短句链保护：普通观察、路线判断、动作安排和信息确认优先写成自然承接句。
- 自然度检测新增连续短句链、短台词链和“不A、不B、也不C”式清单腔识别。
- 连接修复会把短问、短命令、短判断合并为自然承接，或补清对象、方向、条件和动作后果，不改变剧情事实。
- 章节卡生成进一步去正文复述化，摘要优先保持目标、事件、结果、限制和钩子的剧情轨道。

## 1.8.2 更新重点

- 新增 100 章大阶段检查，和 20 章阶段检查叠加使用。
- 自动写到 20/40/60/80 章触发普通阶段检查，写到 100/200/300 章触发大阶段检查。
- 大检查会复盘主线偏移、卷结构、角色成长、伏笔拖欠、爽点密度和后续章节卡是否需要重排。
- 报告最后会输出“阶段建议”，明确提示是否建议点击“继续写”“重排后续章节卡”“重新自动分卷”“保存检查建议到蓝图”。
- 检查点面板新增对应操作按钮，方便按报告建议继续处理。

## 1.8.1 更新重点

- 自动写作台账扩容：角色记忆 300 条、伏笔 240 条、读者期待 160 条、爽点 160 条、系统规则 200 条、功能日历 240 条。
- 新增角色长期摘要：按角色压缩长期关系、状态和口吻变化，减少长篇后期角色记忆丢失。
- 自动写作进度区显示台账当前数量和上限，便于判断长篇记忆容量。

- 新增可编辑蓝图和台账重建入口，便于修正已有项目。

## 写作质量策略

软件不会只依赖一句“写得自然”的提示词，而是把自然读感拆成多个可检查的维度：

- 章节卡不规定正文口吻，避免正文被卡片写法字段绑死。
- 对话优先服务当场关系、行动和信息差，避免长期写成状态播报。
- 紧急短句可以保留，但连续半截命令和否定清单会触发检查。
- 旁白尽量用现场证据、动作、物件反馈和人物选择承载意义。
- 降低 `不是A，也不是B，而是C`、`一条A，一块B，一个C` 这类机械解释升格句式。
- 系统提示要求整行使用 `【】`，避免半框格式污染正文。
- 环境描写优先服务行动，只保留会改变路线、视线、风险或选择的细节。

## 技术结构

- 前端：React + Vite
- 后端：Express
- 桌面壳：Electron
- 数据存储：本地 JSON 数据库
- 打包工具：electron-builder

## 目录说明

- `src/`：前端界面与交互逻辑。
- `server.js`：后端 API、模型调用、自动写作链路和自然度检查。
- `electron/`：Electron 主进程和桌面运行入口。
- `scripts/`：构建、图标生成、测试和本地实验脚本。
- `naturalnessGate.js`：自然读感问题分级和修复优先级。
- `promptComposer.js`：Prompt 组合辅助模块。
- `projectRepository.js`：本地项目存储辅助模块。

## 本地开发

安装依赖：

```bash
npm install
```

启动桌面开发环境：

```bash
npm run desktop:dev
```

启动 Web 构建检查：

```bash
npm run build
```

运行 parser 回归测试：

```bash
npm run test:parsers
```

## 打包桌面安装包

```bash
npm run dist:desktop
```

打包产物默认输出到当前版本对应的 `release-x.y.z/` 目录。

如需单独生成图标：

```bash
npm run generate-icons
```

## 模型配置

在软件的 AI 配置页面填写：

- API Key
- Base URL
- 模型名称
- 当前激活配置
- 路由模式

建议使用混合路由：规划阶段使用较快模型，正文写作阶段使用质量更稳定的模型。
